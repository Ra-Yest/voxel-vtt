# Voxel VTT

Настольная 3D-среда для мастера ролевых игр на движке VoxelCore с сетевым слоем Neutron. Вся логика написана на Lua.

> **Статус:** MVP-0 в разработке. Автоматические тесты проходят, многопользовательский режим проверен в ограниченном объёме (см. «Известные ограничения»). Игра в интернете без дополнительной настройки безопасности не рекомендуется (см. «Безопасность»).

## Возможности

- Тактическая камера и переключение между видом от первого лица и видом сверху.
- Сетка клеток 3×3 блока, подсветка клетки под курсором.
- Выбор токена мышью, подсветка зоны перемещения и превью маршрута.
- Серверная проверка хода: владелец токена, дальность (5 клеток для игроков), роль Мастера.
- Защита мира: серверный перехватчик отбрасывает изменения блоков, взаимодействие с блоками и спавн сущностей от игроков, не являющихся Мастером.
- Консольные команды работают по тем же правилам, что и сетевые действия: решение принимает один серверный реестр команд.
- Синхронизация позиций токенов между сервером и клиентами.

## Архитектура

Зависимости идут только сверху вниз:

```
core    чистый Lua без вызовов движка: сетка, правила, схемы, логирование
  ↓
net     единственная прослойка над Neutron: каналы, перехватчики, идентичность
  ↓
server  состояние стола, токены, команды, мир
client  камера, выбор, подсветка, превью хода
```

## Требования

- Windows 10/11
- VoxelCore 0.32
- Neutron (сервер и клиент), версия согласована с движком

Движок и Neutron в репозиторий не входят, установите их по официальным инструкциям.

## Запуск

1. Установите VoxelCore 0.32 и Neutron (сервер и клиент).
2. Скопируйте папку `vtt/` в каталог контент-паков и сервера, и клиента (код пака выполняется на обеих сторонах).
3. В `server_config.json` (создаётся при первом запуске сервера в `root/config`) добавьте `"vtt"` в `game.content_packs`. По документации Neutron изменение `content_packs` действует только при создании **нового** мира, существующий мир пак не подхватит.
4. Настройте роли (раздел «Конфигурация ролей») и безопасность (раздел «Безопасность»).
5. Получите роль Мастера (раздел «Первый Мастер»).
6. Запустите сервер и подключите клиент.
7. В игре: `V` — тактический режим, `G` — сетка, ЛКМ — выбор токена и клетки назначения, `T` — чат с командами.

## Команды

Команды вводятся в чате (клавиша `T`), аргументы именованные:

```
/token_spawn cx=<> cz=<> id=<> owner=<identity игрока>
/token_move id=<> cx=<> cz=<>
/token_remove id=<>
/token_owner id=<> owner=<identity игрока>
/block_set x=<> y=<> z=<> id=<>
```

- `cx`, `cz` — координаты клетки (клетка 3×3 блока).
- `id` — идентификатор токена, любая строка, должна быть уникальной (повторный `id` отклоняется).
- `owner` — `identity` игрока, которому принадлежит токен. Необязательный. Без него токен двигает только Мастер. В `/token_owner` пропуск `owner` снимает владельца. `identity` игрока виден в логе сервера в строке `[identity]`.
- `/token_spawn`, `/token_remove`, `/token_owner`, `/block_set` доступны только Мастеру.
- `/token_move` и ход мышью подчиняются одним правилам: Мастер двигает любой токен на любое расстояние, игрок только свой токен и не дальше 5 клеток.
- При отказе игрок получает причину в чате (для консольных команд). При ходе мышью причина пишется только в лог сервера.

## Конфигурация ролей

Меньшее значение `priority` означает более высокую роль

```json
"roles": {
  "default_role": "member",
  "master": {
    "priority": 1,
    "rules": {
      "allow-content-access": true, "allow-flight": true, "allow-noclip": true,
      "allow-attack": true, "allow-destroy": true, "allow-cheat-movement": true,
      "allow-debug-cheats": true, "allow-fast-interaction": true
    },
    "permissions": { "role_management": true, "time_management": true }
  },
  "member": {
    "priority": 2,
    "rules": {
      "allow-content-access": true, "allow-flight": true, "allow-noclip": true,
      "allow-attack": true, "allow-destroy": true, "allow-cheat-movement": true,
      "allow-debug-cheats": true, "allow-fast-interaction": true
    },
    "permissions": {}
  }
}
```

Важно:
- Флаги `rules` (`allow-*`) в Neutron влияют только на клиент, сервер их не проверяет. Они **не защищают** мир. Защиту ставит пак (перехватчик пакетов и серверный реестр команд), а не конфиг. Поведение клиента с пустой секцией `rules` не проверено, поэтому в примере оставлены значения по умолчанию.
- У роли `member` оставлена пустая таблица `permissions`, чтобы игроки не могли менять роли других.
- Встроенная команда `/role_set` позволяет Мастеру менять роли только игрокам с более низким приоритетом. Второго Мастера с её помощью назначить нельзя.

## Первый Мастер

Роль `default_role` присваивается аккаунту один раз, при самом первом входе. Уже существующие аккаунты роль не меняют. Порядок получения Мастера:

1. В `server_config.json` поставьте `"default_role": "master"` и задайте `whitelist` с одним новым именем игрока, под которым ещё никто не заходил.
2. Запустите сервер и зайдите под этим именем. В логе сервера в строке `[identity]` должна быть роль `master`.
3. Остановите сервер штатно командой `stop` (сохраняет аккаунты).
4. Поставьте `"default_role": "member"`, добавьте в `whitelist` имена остальных игроков и запустите сервер снова.

Не оставляйте сервер с `default_role = "master"` открытым для других игроков.

## Безопасность

- Имя игрока и `identity` присылает клиент. При `"password_auth": false` любой клиент может войти с чужим `identity` и получить роль и токены этого аккаунта. Для игры вне доверенной локальной сети включите `"password_auth": true` и используйте `whitelist`.
- Роль Мастера определяется по полю `role` аккаунта на сервере. Пак не изменяет роли аккаунтов.
- Защита мира перехватывает на сервере пакеты изменения блоков и спавна сущностей. Игроки, тем не менее, могут летать и проходить сквозь блоки (серверные проверки Neutron для этого отсутствуют), на карту это не влияет.

## Известные ограничения

- Модели других игроков могут не отображаться: в журнале сервера появляется строка `spawn of an unregistered entity: base:player`. Это не влияет на работу токенов.
- Интерфейс панели Мастера, чат и броски пока не реализованы.
